# AlemEdu

Площадка образовательных задач: организация публикует потребность, команды предлагают решения, заказчик рассматривает отклики и вручную выбирает исполнителей.

Полный проект: Laravel 12 / PHP / SQLite в `backend/`, Vue 3 / Vite / Axios в `frontend/`. Основная ветка для запуска: `main`.

## Один запуск на своём компьютере

- **Windows с PHP и Node.js:** дважды нажмите `START.cmd`. Откроется http://127.0.0.1:8080. Нужен только один терминал; сайт и API работают вместе. Зависимости и демоданные подготавливаются автоматически. Для первого запуска нужен Composer.
- **Любая ОС с Docker:** выполните из корня `docker compose up --build -d`, откройте http://localhost:8080. PHP, Node.js и Composer отдельно устанавливать не нужно. База сохраняется в Docker volume между перезапусками.

Если порт занят: `powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 8085` либо задайте `PORT=8085` для Docker Compose.

## Размещение без своего компьютера

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/BAITC-Hacks/hack-c8a98f95-1465)

Войдите в Render и подтвердите Blueprint. Репозиторий уже содержит Dockerfile и `render.yaml`; вручную настраивать команды сборки и адрес API не нужно. После завершения сборки получите HTTPS-адрес `onrender.com`.

**Ограничения бесплатного Render:** сервис засыпает после 15 минут простоя, первый запуск может занять около минуты. Изменения SQLite теряются при перезапуске, исходные демоданные восстанавливаются автоматически. Для сохранения данных нужен платный сервис с диском `/data`. [Документация Render](https://render.com/docs/free).

[Инструкция по размещению и остановке](docs/DEPLOY.md). Постоянный хостинг требует вашего аккаунта; текущая опубликованная ссылка выше использует временный туннель.

## Требования для разработки

- Node.js 22.12+ и npm.
- PHP 8.2+ и Composer 2.
- PHP-расширения `pdo_sqlite`, `mbstring`, `openssl`, `fileinfo`, `dom`, `xml`, `xmlwriter`; `zip` и `curl` для установки зависимостей.
- Свободные порты: `5173` для сайта и `18081` для API.

## Разработка на Windows

Откройте два терминала в корне репозитория.

Первый терминал:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\backend\start.ps1
```

Скрипт находит PHP в PATH, локальной папке AlemEdu или XAMPP, устанавливает зависимости при необходимости, подготавливает ключ, SQLite и демоданные. Нужен Composer в PATH либо `%LOCALAPPDATA%\AlemEdu\tools\composer.phar`.

Второй терминал:

```powershell
cd frontend
npm.cmd ci
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm.cmd run dev
```

Откройте **http://127.0.0.1:5173/**. Панель заказчика: **http://127.0.0.1:5173/workspace**. Проверка API: http://127.0.0.1:18081/api/health.

Оставьте оба терминала открытыми. `Ctrl+C` останавливает соответствующий сервер. Повторный запуск backend сохраняет существующие данные.

## Разработка на Linux / macOS

Первый терминал из корня репозитория:

```sh
cd backend
composer install
composer setup
composer dev
```

Второй терминал, при первой настройке:

```sh
cd frontend
npm ci
cp .env.example .env
npm run dev
```

Адреса те же: сайт `5173`, API `18081`. При последующих запусках не заменяйте настроенный `.env`.

## Соединение frontend и backend

В `frontend/.env`:

```dotenv
VITE_API_URL=http://127.0.0.1:18081/api
```

После смены адреса перезапустите Vite. Если файл остался от предыдущего этапа и содержит порт `8000`, замените его на `18081`. При другом порте backend используйте `start.ps1 -Port 18083` или `php artisan serve --host=127.0.0.1 --port=18083 --no-reload` и тот же порт в `VITE_API_URL`.

Backend разрешает frontend `http://127.0.0.1:5173` и `http://localhost:5173`. Для другого адреса добавьте его в `CORS_ALLOWED_ORIGINS` в `backend/.env`, выполните `php artisan config:clear` и перезапустите backend. В переменных `VITE_*` не должно быть секретов.

## Подключение OpenAI

AI-помощник поддерживает настоящий OpenAI API. По умолчанию без ключа включён явно обозначенный локальный деморежим. Чтобы активировать OpenAI, из `backend/` выполните:

```sh
php artisan ai:configure
php artisan ai:check
```

На Windows с XAMPP: `& C:\xampp\php\php.exe artisan ai:configure` и `& C:\xampp\php\php.exe artisan ai:check`.

Первая команда запрашивает ключ со скрытым вводом и записывает его только в игнорируемый `backend/.env`. Вторая делает один платный запрос с синтетическим описанием и проверяет подключение. Ключ не нужно отправлять в чат или помещать во frontend. После настройки перезапустите backend.

Модель по умолчанию: `gpt-5.4-mini`, настройка: `OPENAI_MODEL`. После сохранения черновика сайт покажет вопросы с отметкой OpenAI и названием модели. При ошибке OpenAI заглушка не подставляется. AI не меняет баллы, публикацию или решения заказчика.

[Промпт, режимы, лимиты, приватность и диагностика](backend/docs/AI.md). Для автономного показа: `AI_PROVIDER=mock`. Не открывайте демосервер с платным ключом в интернет: сначала необходима настоящая авторизация.

## Полный сценарий

1. Выберите «Демо-заказчик 1». Создайте черновик, уточните описание и подтвердите публикацию.
2. Найдите задачу в каталоге. Карточка показывает учреждение, регион, охват и готовность описания.
3. Переключитесь на команду, например Qadam. Отправьте идею, план и сроки.
4. Вернитесь к заказчику: «Мой кабинет» → «Отклики» нужной задачи. Рассмотрите предложения, нажмите «Выбрать» или «Отклонить».
5. Откройте кабинет команды: решение сохранено и видно после обновления страницы.

Прямой адрес панели: `/tasks/:id/offers`. Отклики видит только владелец задачи; команда видит свои предложения в кабинете. Панель показывает загрузку, пустой список, ошибки и позволяет повторить запрос. Решение меняется на экране только после успешного ответа API.

### Правила предметной области

- `Task.status` имеет только значения `draft` и `published`. Рейтинг не управляет публикацией: задача с 0 баллов может быть опубликована и видна в каталоге.
- `score` и `scoreBreakdown` отражают полноту подтверждённого описания и приходят из API. `readinessLevel` не является статусом публикации.
- Охват `institution` означает задачу для своего учреждения. Её видят все команды, в том числе из других организаций, и могут отправлять отклики.
- Новый отклик имеет `decision: pending`. Заказчик вручную устанавливает `selected` или `rejected`. Можно выбрать несколько команд и пересмотреть решение. Другие отклики автоматически не отклоняются.
- Решение не меняет `Task.status` и не вычисляется из рейтинга.

## Проверки

Backend, из `backend/`:

```sh
php artisan test
php vendor/bin/pint --test
composer validate --strict
```

На Windows без PHP в PATH: `& C:\xampp\php\php.exe artisan test`.

Frontend, из `frontend/`:

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

На Windows можно использовать `npm.cmd` и `npx.cmd`.

По умолчанию Playwright сам поднимает API на `18082` с новой временной SQLite-базой и сайт на `5174`. Данные основного демо не затрагиваются. Для PHP не в PATH задайте `E2E_PHP`; XAMPP на Windows находится автоматически. Тесты охватывают публикацию, каталог, внешнюю команду, решения, права доступа, сетевые ошибки и экраны 1366×768, 1920×1080, 390×844.

Отчёт: `frontend/playwright-report/index.html`, скриншоты: `frontend/test-results/`. GitHub Actions запускает frontend, backend и полный сценарий на изолированной базе.

## Ограничения демоверсии

Демопрофили заменяют регистрацию и настоящую аутентификацию. Для настоящего AI нужен настроенный OpenAI API; без ключа проект запускается в явно обозначенном деморежиме. Для публичного размещения нужны настоящая авторизация и производственные настройки сервера.
