# AlemEdu Frontend — участник 2

Vue 3, Vue Router, Vite и Axios. Интерфейс работает с Laravel API участника 1. Рейтинг, уровень готовности и расшифровка приходят из backend; формулы рейтинга во frontend нет.

## Запуск

Нужны Node.js **22.12+** и npm. Для backend — PHP 8.2+, Composer 2 и расширения из [инструкции backend](../backend/README.md).

В первом терминале, из корня репозитория:

```sh
cd backend
composer install
composer setup
composer dev
```

Проверьте `http://127.0.0.1:8000/api/health`. Настройка добавляет демонстрационные профили, задачи и команды.

Во втором терминале:

```sh
cd frontend
npm ci
```

Скопируйте `.env.example` в `.env`:

```sh
# Linux / macOS
cp .env.example .env
```

```powershell
# Windows PowerShell
Copy-Item .env.example .env
```

Затем:

```sh
npm run dev
```

Откройте `http://127.0.0.1:5173`. Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd` вместо `npm`, например `npm.cmd ci` и `npm.cmd run dev`.

## Адрес API

В `frontend/.env`:

```dotenv
VITE_API_URL=http://127.0.0.1:8000/api
```

Укажите полный базовый адрес с `/api`, без адреса конкретного метода. Если backend запущен на порту `18081`, замените порт здесь. После изменения `.env` перезапустите Vite; для готовой сборки выполните сборку заново. Переменные `VITE_*` видны в браузере — секреты в них не размещаются.

Backend разрешает CORS для `http://127.0.0.1:5173` и `http://localhost:5173`. Если используете другой адрес frontend, добавьте его в `CORS_ALLOWED_ORIGINS` в `backend/.env` и перезапустите backend. Для просмотра production-сборки на порту 4173 добавьте `http://127.0.0.1:4173`.

## Проверка основного потока

1. На главной выберите «Я заказчик» и нажмите «Создать задачу». Для конкретного заказчика можно сначала выбрать демопрофиль в верхней панели.
2. Заполните название и исходное описание, создайте черновик. Откроется редактируемая карточка; вопросы AI загрузятся автоматически, если описание содержит хотя бы 3 символа. Если описание короче, дополните поле «Контекст и потребность» и нажмите «Получить вопросы AI».
3. Ответьте на вопросы, дополните поля карточки и явно подтвердите заполненные поля. Сохраните изменения: рейтинг и расшифровка обновятся из ответа API.
4. Для публикации заполните название, организацию, регион, тему и охват. Подтвердите публикацию и опубликуйте задачу.
5. Откройте каталог, найдите задачу по названию. Проверьте фильтры по теме, региону и охвату, сортировку по рейтингу.
6. Откройте подробную страницу, выберите демопрофиль команды и заполните форму отклика. Отправленный отклик доступен команде в кабинете. На странице задачи показано количество откликов.

Демопрофили загружаются из `GET /demo/profiles`; выбранный профиль сохраняется в браузере и передаётся через `X-Demo-Role` и `X-Demo-Id`. Это демонстрационный режим, предусмотренный backend. Вопросы AI формирует локальная заглушка backend — внешний AI-ключ для запуска не нужен.

Изменение содержательного поля снимает его подтверждение до повторного подтверждения. До сохранения карточка показывает последний полученный с сервера рейтинг. Каталог отображает опубликованные задачи; свои черновики доступны заказчику в кабинете.

## Экраны и интеграция

| Адрес | Назначение |
| --- | --- |
| `/` | Главная, выбор роли и пошаговый старт |
| `/guide` | Инструкция для заказчика и команды, объяснение рейтинга |
| `/catalog` | Поиск, фильтры, сортировка и список задач |
| `/tasks/new` | Создание черновика |
| `/tasks/:id/edit` | Вопросы AI, редактирование, рейтинг, публикация |
| `/tasks/:id` | Подробности, количество откликов и форма отклика команды |
| `/workspace` | Задачи заказчика или отклики команды |

[Контракт API](../backend/docs/API.md) описывает поля camelCase, права профилей и ответы. Успешные ответы обёрнуты в `data`; сообщения API и ошибки валидации отображаются в интерфейсе. Экраны показывают загрузку, пустые результаты и возможность повторить запрос после ошибки.

## Проверки и сборка

Из `frontend/`:

```sh
npm test
npm run build
npm run preview
```

`npm test` запускает Vitest. `npm run build` создаёт готовые файлы в `dist/`; `npm run preview` открывает локальную проверку сборки. При размещении `dist/` настройте отдачу `index.html` для маршрутов Vue Router, например `/tasks/5`. Адрес API и CORS должны соответствовать месту размещения.

Для браузерной проверки полного потока нужен работающий backend с демоданными:

```sh
npx playwright install chromium
npm run test:e2e
```

Playwright сам запускает frontend на `127.0.0.1:5173`. Если сайт уже открыт для работы, задайте `E2E_PORT=5174`, чтобы тесты использовали отдельный Vite-сервер, и добавьте этот адрес в CORS тестового backend. По умолчанию тесты обращаются к API на `127.0.0.1:8000/api`. При другом порте задайте одинаковые `E2E_API_URL` и `VITE_API_URL` в окружении запуска тестов. Браузерные тесты создают задачи и отклики, поэтому используйте отдельную локальную или тестовую базу; записи остаются доступны для просмотра после проверки.

[GitHub Actions](../.github/workflows/frontend.yml) устанавливает зависимости через `npm ci`, выполняет модульные тесты и сборку, поднимает Laravel с отдельной SQLite-базой и запускает Playwright в Chromium. При ошибке сохраняет отчёт и трассировки Playwright.

## Если что-то не работает

- Ошибка подключения: проверьте `/api/health`, `VITE_API_URL` и работающий процесс backend.
- Ошибка CORS: проверьте точный адрес браузера в `CORS_ALLOWED_ORIGINS` и перезапустите backend.
- Ответ 401/403: выберите подходящий демопрофиль; чужую задачу редактировать нельзя.
- Ответ 422: исправьте указанные API поля и повторите сохранение.
- После изменения `.env` backend выполните `php artisan config:clear` и перезапустите сервер.
