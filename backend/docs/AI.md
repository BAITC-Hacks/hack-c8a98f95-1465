# AI-помощник: OpenAI и деморежим

Рабочая интеграция с OpenAI находится в `app/Services/OpenAiQuestions.php`.
Используется [Responses API со Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Модель по умолчанию: [gpt-5.4-mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini); её можно заменить через `OPENAI_MODEL` на доступную модель с поддержкой Responses и JSON Schema.

## Активация

Из `backend/`, после обычной подготовки проекта:

```sh
php artisan ai:configure
php artisan ai:check
```

На Windows с XAMPP:

```powershell
cd backend
& C:\xampp\php\php.exe artisan ai:configure
& C:\xampp\php\php.exe artisan ai:check
```

`ai:configure` спрашивает ключ со скрытым вводом и сохраняет его только в локальный `backend/.env`, сохраняя другие настройки. Замена существующего ключа требует подтверждения. Ключ нельзя передавать аргументом команды, вставлять в чат или добавлять в `VITE_*`. `.env` исключён из Git; он содержит секрет в открытом виде и должен быть доступен только владельцу/серверу.

`ai:check` делает **один платный запрос** с синтетическим описанием и печатает полученные вопросы. Без рабочего ключа, доступной модели и средств/квоты API проверка не пройдёт. Автоматические тесты этой команды используют имитацию HTTP, а не внешний API.

После настройки перезапустите backend. Сайт: http://127.0.0.1:5173/tasks/new.
Сохраните описание проблемы: вопросы появятся в редакторе с отметкой `OpenAI · gpt-5.4-mini`. После дополнения полей нажмите «Обновить вопросы». Ошибка API не удаляет черновик или несохранённый текст.

Альтернатива для серверного окружения: настройте переменные среды либо `backend/.env`:

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.4-mini
```

Пустой ключ выше нужно заполнить локально, не в репозитории. Затем `php artisan config:clear` и перезапуск backend. Системные переменные окружения имеют приоритет над `.env`.

## Режимы

- `AI_PROVIDER=auto`: при наличии ключа запрос идёт в OpenAI, без ключа возвращаются локальные вопросы с `mode: mock`.
- `AI_PROVIDER=openai`: требуется настоящее подключение; отсутствие ключа возвращает ошибку настройки.
- `AI_PROVIDER=mock`: полностью автономные детерминированные вопросы, без сети и оплаты.

Сбой OpenAI **не заменяется заглушкой**. В интерфейсе показывается ошибка и доступен повторный запрос. Отметка OpenAI появляется только после успешного ответа; она не служит проверкой связи до запроса.

## Промпт и границы

Готовый системный промпт: [task-questions.txt](../resources/prompts/task-questions.txt).
Он просит 3–7 конкретных вопросов на русском по разным полям задачи, учитывает уже заполненное и запрещает выдумывать факты. Пользовательское описание передаётся отдельно как данные, а не как системная инструкция.

Модель формирует только `topic` и `questions`. Backend самостоятельно вычисляет `missingFields`, сохраняет исходные сведения в `suggestedFields` и назначает идентификаторы вопросов. Ответ проверяется на типы, допустимые поля, уникальность, число и длину вопросов. Вопросы могут быть неточными, поэтому их проверяет заказчик.

Frontend не применяет `suggestedFields` автоматически. AI не пишет в БД, не выставляет баллы, не подтверждает поля, не публикует задачу и не принимает решения по откликам. Низкий рейтинг не мешает публикации; охват учреждения не ограничивает команды.

## Приватность и расходы

- Ключ хранится и используется только на backend. Запросы идут на фиксированный HTTPS-адрес OpenAI; переадресации отключены.
- Отправляются описание и содержательные поля, кроме `contact`. Вместо контакта передаётся только `contactProvided`. Не вставляйте персональные данные и секреты в остальные поля: автоматического обезличивания произвольного текста нет.
- В запросе установлено `store: false`. Это не обещание полного отсутствия хранения у провайдера: учитывайте [политику данных API](https://developers.openai.com/api/docs/guides/your-data).
- Тела ошибок провайдера и транспортные исключения не выводятся клиенту и не записываются этим адаптером в журнал.
- Вход ограничен 20 000 символов суммарно (каждое поле до 10 000), ответ 2500 токенами. Backend ждёт до 40 секунд, frontend до 50 секунд. Автоповторов нет.
- На HTTP-маршруте: 6 запросов в минуту с IP и 100 запросов за суточное окно на сервер. Лимиты в `config/ai.php`, счётчики в Laravel cache. Для нескольких серверов нужен общий cache; дополнительно настройте лимиты проекта OpenAI. Консольная `ai:check` предназначена для администратора и не использует HTTP-лимитер.

Демопрофили не являются аутентификацией. Не выставляйте этот демосервер с платным ключом в публичный интернет до внедрения настоящей авторизации.

## API

`POST /api/ai/questions`, заголовки демозаказчика как в [API.md](API.md).

```json
{
  "description": "Студентам нужен общий календарь консультаций.",
  "fields": { "users": "Студенты первого курса." }
}
```

Успешный ответ содержит `data` с полями `mode`, `topic`, `missingFields`, `questions`, `suggestedFields`, `notice`; в режиме OpenAI добавляется `model`.
Вопрос: `{"id":"clarify_materials","field":"materials","question":"Где сейчас хранится расписание консультаций?"}`.
Допустимы `context`, `users`, `materials`, `constraints`, `expectedOutcome`, `successCriteria`, `contact`.

Ошибки OpenAI имеют `message` и безопасный `code`:

| HTTP | code | Что сделать |
| --- | --- | --- |
| 503 | ai_configuration | Проверить ключ, модель и права проекта API. |
| 503 | ai_quota | Проверить квоту/баланс или повторить позже. |
| 504 | ai_timeout | Проверить сеть, повторить запрос. |
| 502 | ai_provider | Дождаться восстановления OpenAI. |
| 502 | ai_incomplete | Сократить описание и повторить. |
| 502 | ai_refusal | Переформулировать образовательную задачу. |
| 502 | ai_invalid_response | Повторить; непроверенный ответ не применяется. |
| 429 | без code, Retry-After | Достигнут локальный лимит; подождать. |

Ошибки входных данных: 400 (JSON), 422 (поля/размер); права: 401/403. При проблемах TLS проверьте CA-сертификаты PHP (`curl.cainfo`/`openssl.cafile`), не отключайте проверку HTTPS.

## Проверки

`php artisan test` использует `Http::fake` и блокирует случайные внешние запросы в тестах интеграции. `AI_PROVIDER=mock` принудительно задан для PHPUnit и управляемого E2E backend. Playwright отдельно проверяет отображение режима OpenAI, ошибки, повтор и мобильную вёрстку на имитированных ответах. Эти проверки не подтверждают доступность вашей модели и ключа: для этого служит `ai:check`.
