# AlemEdu Backend — участник 1

Laravel 12, PHP 8.2+, SQLite, JSON API `/api`. Интерфейс Vue разрабатывается отдельно в `frontend/`.

## Быстрый запуск

Нужны PHP 8.2+ и Composer 2. Расширения PHP: `pdo_sqlite`, `mbstring`, `openssl`, `fileinfo`, `dom`, `xml`, `xmlwriter`; `curl` и `zip` ускоряют установку зависимостей. Проверить: `php -v`, `php -m`, `composer --version`.

Из корня репозитория:

```sh
cd backend
composer install
composer setup
composer dev
```

`composer setup` создаёт `.env` из `.env.example`, ключ приложения и файл SQLite, применяет миграции и добавляет демоданные. Повторный запуск сохраняет существующие записи и ключ. Секреты и база не коммитятся.

API: http://127.0.0.1:8000/api/health

Если порт занят:

```sh
php artisan serve --host=127.0.0.1 --port=18081 --no-reload
```

На Windows также можно запустить из корня:

```powershell
.\backend\start.ps1 -Port 18081
```

Скрипт ищет PHP 8.2+ в PATH, затем в `%LOCALAPPDATA%\AlemEdu\tools\php` и XAMPP. Если зависимостей нет, запускает Composer, затем подготовку БД и сервер. Наличие переносимого PHP/Composer не обязательно для других участников — подойдёт их собственная установка. XAMPP с PHP 8.0 не подходит.

Параметр `--no-reload` обеспечивает предсказуемый запуск на Windows. Изменения PHP-кода видны сразу; после изменения `.env` перезапустите сервер.

## Что готово

- Модели Task, Team, Offer, миграция SQLite и связи между ними.
- Создание, изменение, чтение и подтверждённая публикация задач.
- Прозрачный рейтинг, подтверждение полей, пересчёт после правок.
- Каталог с фильтрами, поиском на русском и сортировкой.
- Локальная предсказуемая AI-заглушка с минимум тремя вопросами.
- Отклики и ручные решения; можно выбрать несколько команд.
- Два демопрофиля заказчиков, пять команд, пять задач и пять откликов.
- Проверки PHPUnit, реальный HTTP-сценарий и GitHub Actions.

## Передача участнику 2

1. Получить код из `main` после объединения `feature/backend-api`.
2. Запустить backend по инструкции выше.
3. Открыть [контракт API](docs/API.md): все поля JSON используют camelCase.
4. Взять [готовые HTTP-запросы](docs/alemedu.http) и [JSON-примеры](docs/examples/).
5. Для Axios использовать пример из контракта и переключатель демопрофилей.

Все успешные ответы: `{"data": ...}`. Ошибки: `{"message": "...", "errors": {...}}`; `errors` есть при валидации. Внешний AI API, регистрация, пароли, загрузка файлов и frontend не входят в этот этап.

## Роли без регистрации

`GET /api/demo/profiles` возвращает доступные профили. Для действий отправляйте заголовки:

```http
X-Demo-Role: customer
X-Demo-Id: 1
```

Для команды: `X-Demo-Role: team`, `X-Demo-Id: 1..5`.

Владелец задачи определяется сервером из выбранного заказчика. Команда отклика определяется из выбранной команды. Чужой заказчик не может редактировать задачу, читать отклики или принимать решение; студент не может публиковать задачи. Каталог и опубликованная карточка доступны без заголовков.

Это переключение демонстрационных профилей, а не реальная аутентификация. `DEMO_MODE=false` отключает действия от этих профилей; до публичного рабочего запуска потребуется настоящая авторизация.

## Рейтинг и публикация

| Поле | Баллы |
|---|---:|
| context | 20 |
| materials | 20 |
| expectedOutcome | 15 |
| successCriteria | 15 |
| constraints | 10 |
| users | 10 |
| contact | 10 |

Баллы начисляются за непустое поле, перечисленное в `confirmedFields`. Пробелы и пустые значения баллов не дают. Текст «данных нет» допустим: он явно описывает ситуацию.

Уровни: 0–39 `draft`, 40–69 `working`, 70–89 `ready`, 90–100 `priority`. `readinessLevel` и статус публикации `status` независимы.

Создание требует только `title`. Для публикации нужны `title`, `organization`, `region`, `category`, допустимый `scope` и `confirmed: true`. Семь содержательных полей могут быть пустыми, поэтому можно опубликовать задачу даже с 0 баллов. Это согласование двух требований ТЗ: структура карточки содержит все поля, а неполнота описания не блокирует публикацию.

`POST /tasks/{id}/publish` подтверждает все заполненные содержательные поля. `PUT` без `confirmedFields` снимает подтверждение только с изменённых полей. Если передать `confirmedFields`, список полностью заменяет предыдущий и означает явное подтверждение пользователем. Нельзя подтверждать пустые поля. После редактирования опубликованная задача остаётся видимой; рейтинг пересчитывается.

Охват `institution` не ограничивает просмотр и отклики других команд. `preferredOrganization` только меняет порядок в каталоге.

## Демо и проверка

На чистой БД:

| ID | Задача | Статус | Баллы | Заказчик |
|---|---|---|---:|---:|
| 1 | Разговорный английский | draft | 20 | 1 |
| 2 | Расписание консультаций | published | 60 | 1 |
| 3 | Поиск учебных книг | published | 75 | 1 |
| 4 | Обратная связь по занятиям | published | 90 | 1 |
| 5 | Навигация по кампусу | published | 100 | 2 |

Все названия, контакты и материалы синтетические. Пять исходных описаний доступны через `GET /api/demo/briefs`. Отклики привязаны только к опубликованным задачам и начинаются со статуса `pending`.

```sh
php artisan test
vendor/bin/pint --test
composer validate --strict
```

На Windows для Pint: `php vendor/bin/pint --test`.

После запуска HTTP-сервера, в другом терминале:

```sh
php scripts/smoke.php http://127.0.0.1:8000/api
```

Скрипт создаёт новую задачу с 20 баллами, дополняет её до 100, публикует, отправляет отклик и выбирает команду. Он оставляет эти две новые записи для осмотра. Для другого порта поменяйте URL.

Для намеренного сброса только локальных демоданных: `php artisan migrate:fresh --seed`. Команда удаляет таблицы текущей БД. Обычный повторный `composer setup` ничего не сбрасывает.

## Частые проблемы

- `could not find driver`: включите `extension=pdo_sqlite` в активном `php.ini`; его путь показывает `php --ini`.
- Нет файла SQLite или таблиц: запустите `composer setup` из `backend/`.
- Ответ 401: добавьте оба заголовка демопрофиля.
- Ответ 403: выбранная роль или владелец не подходят.
- Ответ 422: покажите пользователю `errors` по названиям полей.
- Ошибка CORS: добавьте адрес Vue в `CORS_ALLOWED_ORIGINS` через запятую и перезапустите backend.
- После изменения конфигурации: `php artisan config:clear`.
